## 3. Problemas encontrados e corrigidos na integração

1. **Props de página sombreando props compartilhadas (crash em runtime com HTTP 200).** `settings/general`, `envelopes/evidence` e `admin/organizations/show` enviavam uma prop `organization` sem `plan/role/permissions`; o shell (`OrgSwitcher`, `AccountMenu`, `AppSidebar`) quebrava (`Cannot read properties of undefined (reading 'name')`) em **todas** as páginas de Configurações e derivadas. Correções: `HandleInertiaRequests::currentOrganizationProps()` passou a ser público e é **mesclado** na prop `organization` de `settings/general` e `envelopes/evidence`; no painel interno as props foram renomeadas para `customer` (show) e `customers` (index) — ver `docs/frontend.md` › "Props de página × props compartilhadas". `AccountMenu` ficou resiliente (`permissions?.`). O smoke test falha se isso voltar a acontecer.
2. **`sign/show` quebrava com o esqueleto do backend** (`envelope: null`, `recipient: null` na tela `invalid`): props tipadas como anuláveis e renderização antecipada do card "Link inválido".
3. **`members/index`**: helpers Wayfinder tipam `{membership}` como `number` (chave inteira) e a página passava `string` — `Number(member.id)` nas quatro chamadas.
4. **Proxies confiáveis**: `env('TRUSTED_PROXIES')` em `bootstrap/app.php` devolvia `null` com `config:cache` (nenhum proxy confiável em produção → IP errado nos aceites). Movido para `AppServiceProvider::configureTrustedProxies()` lendo `config('assinavelox.trusted_proxies')`.
5. **PHPStan (88 → 0)**: `fopen` sem verificação de `false` nos exports CSV; `random_bytes` com tamanho não garantido; `findOrFail` com tipo ambíguo em `Invitations::accept`; parâmetros sem tipo; `?->` redundante sob `??`; `UserRefResource::ref` ganhou tipo de retorno condicional; `config/horizon.php` (`Str::slug` com `env()` não-string).
6. **`npm run check`** falhava por formatação de `docs/design/**` (mocks e contratos, não editáveis) — excluídos em `vite.config.ts` (`fmt`/`lint.ignorePatterns`); demais `docs/**`, `tests/Fixtures/README.md` e `tools/pdftool/README.md` formatados.
7. **`.env.example`**: chaves do pdftool listadas por A3 (`PDFTOOL_TIMEOUT_SECONDS`, `PDFTOOL_SIGN_TIMEOUT_SECONDS`, `PDFTOOL_TMP_PATH`, `PDFTOOL_TRUST_ROOTS`, `LIBREOFFICE_TIMEOUT_SECONDS`, `COMPANY_CERT_REASON`, `COMPANY_CERT_LOCATION`) com comentários em PT-BR; corrigido o comentário "ausentes → adaptadores fake" (não é exato).
8. `bootstrap/providers.php` registra `App\Integrations\IntegrationsServiceProvider`; `config/assinavelox.php` não duplica chaves de `config/pdftool.php` (conferido).

## 3-A. Rodada de revisão e verificação final (FIX-1, FIX-2, V1)

Revisores adversariais deixaram 20 testes falhando em `tests/Feature/Review/*` documentando achados reais. FIX-1 tratou domínio/segurança, FIX-2 tratou cópia/design e V1 integrou os dois, verificou tudo e fez o QA visual.

### Domínio e segurança (FIX-1)

1. **Cadastro com token de convite alheio.** `CreateNewUser` resolvia o convite só pelo token. Agora o e-mail do cadastro é normalizado e comparado com o do convite; se divergir, o convite é descartado (segue pendente), a chave `invitation.pending_token` sai da sessão e nada da organização convidante toca o novo usuário.
2. **Verificação de e-mail não aplicada.** `App\Models\User` passou a implementar `MustVerifyEmail` — sem a interface, `EnsureEmailIsVerified` deixava passar qualquer usuário. Trocar o e-mail no perfil zera `email_verified_at` **e** dispara `sendEmailVerificationNotification()`.
3. **Reenvio de convite e assentos.** `Invitations::resend()` não ressuscita mais convites revogados (revogar é terminal); `SeatUsage` virou o ponto único de decisão (`occupiesSeat`, `hasAvailableForResend`, `unavailableMessage`) e passou a barrar também o reenvio de convite expirado e a reativação de membership suspensa sem assento livre.
4. **Exclusão de conta.** Novo `App\Services\Accounts\AccountDeletion`: recusa (mensagem PT-BR, antes do logout) quando o usuário é o último owner ativo de alguma organização ou quando é autor de envelopes. A FK `envelopes.created_by_user_id` continua `RESTRICT` conforme `docs/banco-de-dados.md` §4.2 ("Autor é parte da evidência") — a integridade é garantida na aplicação, sem migration nova.
5. **`organizations[].plan_name` no switcher.** O escopo global de organização escondia as assinaturas das demais organizações e todas caíam em "Grátis". `HandleInertiaRequests::planNamesFor()` consulta `Subscription::withoutOrganizationScope()` uma vez para todos os ids.
6. **URIs da conta em PT-BR.** `settings/profile` → `/perfil`, `settings/security` → `/perfil/seguranca`, `settings/password` → `/perfil/senha`; os **nomes** de rota (`profile.edit`, `security.edit`, `user-password.update`) continuam iguais. Os dois `Route::redirect` do kit foram removidos.
7. **Jargão interno em mensagens flash.** O sufixo "(Wave B)" saiu de seis mensagens de `app/Http/Controllers/**`; `greeting.date_label` do dashboard passou a `l, j \d\e F \d\e Y` ("Terça-feira, 8 de setembro de 2026"), conforme DESIGN §6.2.

### Cópia e design (FIX-2)

8. **Rótulo do badge de signatário.** `RecipientStatus::label()` devolve "Pendente" para `pending|notified|viewed` e `note()` cobre os sete estados, espelhando `recipientStatusNotes` de `resources/js/lib/labels.ts` (ROUTES §6.2: o badge âmbar é "Pendente"; "Enviado · não visualizou" é a _nota_).
9. **Jargão "Wave B" na interface.** Trocado por "em breve" / "Em construção" em `envelopes/show`, `envelopes/wizard`, `settings/billing` e `sign/show`. Não foi usado o padrão `Phase2EmptyState`: RECONCILIACAO enumera o que é Fase 2 e visualizador de PDF, wizard, OTP e captura de assinatura não estão na lista — são Fase 1 ainda não construídos.
10. **Acessibilidade em inglês no kit shadcn.** `breadcrumb`, `sheet`, `spinner`, `sidebar` e `command` com `aria-label` / `sr-only` / textos padrão em PT-BR.
11. **Fonte Caveat.** Adicionada ao `vite.config.ts` (peso 600, `preload: false`), servida junto com Exo 2; `--font-hand` já apontava para ela.

### Integração e QA (V1)

12. **`RecipientResource::statusLabel()` devolvia "Aguarda a vez" como rótulo do BADGE.** Inconsistência remanescente entre os dois agentes: contrariava ROUTES §6.2 e duplicava o texto, porque `envelopes/show.tsx` já renderiza "Aguarda a vez" como nota. O override foi removido; o badge volta a ser "Pendente".
13. **Página em branco em qualquer 403/404/500 de rota não casada.** As páginas `errors/*` usam `PublicLayout`, que lia `auth.user`. Quando a URI não casa nenhuma rota, o grupo `web` (e portanto `HandleInertiaRequests`) não roda e **nenhuma** prop compartilhada chega: `TypeError: Cannot read properties of undefined (reading 'user')` e tela branca. `PublicLayout` ganhou fallback para `auth` ausente.
14. **Mensagem do framework, em inglês, exibida ao usuário.** A página 404 mostrava "The route … could not be found."; a de route-model-binding mostraria "No query results for model [App\Models\Envelope] 01K…". `bootstrap/app.php` passou a filtrar mensagens geradas pelo framework e só repassa as escritas pela aplicação (`abort(404, 'Recibo indisponível.')`, `abort(403, 'Acesso restrito à equipe AssinaVelox.')`).
15. **Organização sumia da casca em `/perfil` e `/perfil/seguranca`.** Essas rotas ficam fora do middleware `org` de propósito (usuário sem organização precisa alcançá-las), mas ROUTES §0.3 diz que `organization` só é null em rotas platform-admin e guest. Na prática desapareciam o switcher, o badge de Documentos, os itens "Geral e segurança" / "Padrões de assinatura" / "Plano e cobrança" do rail e o breadcrumb da organização. `HandleInertiaRequests` ganhou `shellMembership()`: resolve a membership **apenas para exibição** (sessão → `users.current_organization_id` → primeira ativa), nunca em rotas `admin/*`, e usa `CurrentOrganization::runAs()` para montar `organization` e `counts` sem deixar o escopo global ligado depois.
16. **Legenda do KPI "Documentos enviados" com "vs." duplicado.** Saía "vs. 2 vs. agosto": `DashboardController::period()` devolvia o rótulo já com "vs." e `dashboard.tsx` prefixa outro. Os rótulos viraram "em agosto" / "nos 90 dias anteriores" / "nos 12 meses anteriores" → "vs. 2 em agosto", exatamente como o mock ("vs. 132 em agosto").
17. **Ações do cabeçalho do documento fora da ordem e da hierarquia do mock.** DESIGN §6.4 especifica `[Baixar] [Lembrar pendentes] [⋯]` com "Lembrar pendentes" como ação primária; estava invertido. Também faltavam "Criado por {nome} em {data}" na linha de metadados e a linha "Ordem de assinatura: **sequencial**" no topo da aba Signatários.
18. **"Nenhum assinatura" / "Nenhum conta".** `TablePagination` fixava o artigo masculino no estado vazio. Ganhou a prop `gender` (`'m' | 'f'`), usada em Assinaturas e no painel interno.
19. **Seeder de demonstração: subpasta "Comerciais".** Era criada com `parent_id` (`childOf`), mas a listagem só exibe pastas raiz: quatro documentos apareciam com Pasta = "Comerciais" e a pasta não existia na árvore lateral. `ROUTES_AND_PAGES.md` (glossário) diz "Pasta | `Folder` | **Sem hierarquia na Fase 1**" — a pasta virou raiz.
20. **Seeder de demonstração: "Expirado" com data no futuro.** `expires_at` = envio + `default_expiration_days`, e o envelope expirado nascia entre 2 e 45 dias atrás, então costumava expirar depois de hoje ("Expirado · 22 set" com hoje = 8 set). O envelope `Expired` agora nasce com pelo menos `default_expiration_days + 3` dias de idade.

## 7. Comandos

```bash
# Dependências e chave
composer install && npm install
cp .env.example .env && php -d extension=intl artisan key:generate

# Banco (MySQL do .env) + seeders de demonstração
php -d extension=intl artisan migrate:fresh --seed

# Alternativa sem tocar no MySQL (SQLite próprio)
touch database/dev.sqlite
DB_CONNECTION=sqlite DB_DATABASE=database/dev.sqlite php -d extension=intl artisan migrate:fresh --seed

# Desenvolvimento
php -d extension=intl artisan serve            # http://localhost:8000
npm run dev                                    # Vite com HMR (ou `composer run dev` = `php artisan dev`)
php -d extension=intl artisan queue:work --queue=default,conversions,notifications,finalization,billing

# Build de produção do front (obrigatório para o smoke test de CSP e para servir sem `npm run dev`)
npm run build

# Helpers TS de rotas (rodar após alterar routes/*.php)
php -d extension=intl artisan wayfinder:generate --with-form

# Qualidade
php -d extension=intl artisan test
vendor/bin/pint --dirty
vendor/bin/phpstan analyse
npm run types:check && npm run check

# pdftool (Python) — autoteste
php -d extension=intl artisan pdftool:selftest
```

Observações: a extensão `intl` não está no `php.ini` local (por isso `-d extension=intl`); filas em dev usam o driver `database`; Horizon/Redis só em produção (`config/horizon.php`).
